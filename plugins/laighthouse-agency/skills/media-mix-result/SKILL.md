> ⚡ **thinking 지침**: thinking은 최대한 짧게 유지한다. 조건 확인 → MCP 호출 → 스크립트 실행 → 완료 순서로 진행한다.

## 역할

라이트하우스 MCP 의 미디어믹스 job 결과를 **라이트하우스 웹 결과 화면(`/m/media-mix/{jobId}`)과 같은 모양의 HTML 한 파일**로 만든다.
구성: 제목(제안 달) · 요청 조건 → 확인할 내용(경고) → 요약 수치 4개 → 매체별 요약(현재 실적 · 제안) →
진단(접힘: 학습 기간 · 표본 · 요일 효과 · 계산 시간). 실패 · 취소된 job 은 사유 배너로 나온다.

- 렌더링은 **미리 검증된 asset 스크립트**만 한다(`.py`/`.js` 신규 작성, HTML 직접 작성 금지).
  - `assets/build_report.py` — 저장된 `get_media_mix_job` 응답 → 최종 HTML 1개. 숫자를 계산하지 않고 응답을 그대로 넣는다.
  - `assets/mm_view.js` · `assets/mm_view.css` — 웹 결과 화면과 같은 계산 · 모양(빌더가 인라인한다).

## 데이터 처리 원칙 (절대 지침)

> 🚫 **MCP 응답은 원문 그대로 빌더에 넘긴다.** 저장 훅이 응답을 파일로 남기고 빌더가 그 파일을 읽는다 — 응답의 요약(`summary`)·
> 진단(`diagnostics`)을 옮겨 적거나, 응답 파일을 Read 로 열지 않는다. 합산 · 재계산 · 추정 금지.
>
> 🚫 job 을 새로 만드는 `create_media_mix_job` 은 **쓰기**다(1~수 분 계산이 돈다). 사용자가 조건을 확인하기 전에는 부르지 않는다.

## 입력

| 경우 | 사용자가 주는 것 |
|---|---|
| 이미 있는 결과 보기 | 브랜드 이름. job 은 B-0 에서 내가 실행한 job 목록을 보여 주고 고르게 한다(job id 를 받았으면 그대로 쓴다) |
| 새로 실행 | 브랜드 이름 + 아래 「새로 실행할 때 확인할 조건」 |

## 실행 순서

### A. 새로 실행할 때

1. `list_media_mix_metrics(brand_name)` — 비용 · 성과 지표 후보(`{name, unit}`)를 받는다. 에러(권한 · 미디어믹스 꺼짐 · 마트 없음)는 그대로 전한다.
2. **조건을 사용자에게 한 번에 확인받는다** — 말하지 않은 값은 추측하지 않고 묻는다. 학습 방식 · VAT 처리 등 나머지는 서버가 기본값으로 정하므로 묻지 않는다.

   | 조건 | 인자 |
   |---|---|
   | 제안받을 달(예산을 배분할 달) | `target_month` (`YYYY-MM`). 그 전월(기준 달) 실적으로 계산한다 — 전월 데이터가 다 들어온 뒤에 돌려야 정확하다 |
   | 비용 지표 · 성과 지표 | `cost_metric`·`revenue_metric` (1번 후보 중 서로 다른 둘) |
   | 제안받을 달의 예산(원, VAT 제외 Net) | `target_budget` |
3. 확인받으면 `create_media_mix_job(...)` 1회 → `id`. `created: false` 면 내가 같은 조건으로 이미 돌리고 있는 job 을 받은 것이다(사용자에게 알린다).
   `status: "failed"` 와 `error` 가 오면 큐에 넣지 못한 것이다 — 사유를 전하고 멈춘다.
4. **끝날 때까지 기다린다**: `get_media_mix_job(brand_name, job_id)`(기본 인자 — 진단 없이 상태만)를 부르고, `status` 가
   `pending`·`running` 이면 `python3 -c "import time; time.sleep(20)"` 로 기다렸다가 다시 부른다. 보통 1~수 분 걸린다.
   10분이 넘도록 끝나지 않으면 사용자에게 알리고 멈춘다(나중에 B 에서 목록으로 골라 결과를 볼 수 있다).
5. `succeeded`·`failed`·`canceled` 가 되면 B-1 부터 한다.

### B. 결과 보고서 만들기

0. A 를 거치지 않은 경우(이미 있는 결과 보기) 결과를 볼 job 을 정한다.
   - 사용자가 job id 를 줬으면 그대로 쓴다.
   - 도구 목록에 `list_media_mix_jobs` 가 없으면(이 조직에는 아직 열리지 않은 도구다) 부르지 말고 job id 를 직접 달라고 한다.
     이 대화에서 A 로 실행한 job 이면 그 id 를 쓴다.
   - 아니면 `list_media_mix_jobs(brand_name)` 1회. 이 브랜드에서 **내가 실행한** job 이 최신순으로 온다(최대 50개, 결과 행 없음).
     다른 사람이 실행한 job 은 목록에 없고 열어 볼 수도 없다.
   - 최근 10개를 아래 표로 번호를 매겨 보여 주고 사용자가 하나를 고르게 한다. 찾는 job 이 없다고 하면 나머지를 마저 보여 준다.
     50개보다 오래된 job 은 목록에 없으니 job id 를 직접 달라고 한다. 사용자가 이미 달 · 예산 등을 말했으면 맞는 행을 짚어 확인만 받는다.
     고르기 전에는 다음으로 넘어가지 않는다. 목록이 비었으면 이 브랜드에서 실행한 미디어믹스가 없다고 알리고 A(새로 실행)를 제안한다.

     | 번호 | 제안받을 달 | 예산(원) | 비용 · 성과 지표 | 상태 | 실행 시각(KST) |
     |---|---|---|---|---|---|
     | 1 | `request.target_month` | `request.target_budget`(천 단위 쉼표) | `request.cost_metric` · `request.revenue_metric` | `status` → `succeeded` 완료 · `running` 계산 중 · `pending` 대기 · `failed` 실패 · `canceled` 취소 | `created_at`(UTC)에 9시간을 더해 `MM-DD HH:mm`. 더해서 24시를 넘으면 날짜도 하루 넘긴다 |

   - 상태를 본다. 목록에서 고른 job 이 완료 · 실패 · 취소면 바로 1번으로 간다. job id 를 직접 받았거나 고른 job 이 대기 · 계산 중이면
     `get_media_mix_job(brand_name, job_id)`(기본 인자)로 상태를 본다. 에러(없는 job · 다른 사람의 job · 권한 등)가 오면 원문을 전하고 멈춘다.
     `pending`·`running` 이면 A-4 대로 끝날 때까지 기다린다. 10분이 넘으면 그 상태로 1번부터 해서 진행 중 보고서를 낸다.
1. `get_media_mix_job(brand_name, job_id, include_diagnostics=true)` **1회**. 배분 행(`include_allocation`)은 보고서에 쓰지 않으니 켜지 않는다. 저장 훅이 응답을 남기므로 진단은 읽거나 옮기지 않는다.
2. 빌드:
   ```
   python3 assets/build_report.py --brand <브랜드> --job-id <job id>
   ```
   출력 JSON:
   - `out` — 완성된 HTML 경로(`~/Downloads/laighthouse-reports/{브랜드}_media-mix_{제안 달}_{id 앞 8자}.html`). 바꿀 때만 `--out`.
   - `missing` — 그 호출을 그대로 다시 보내고 2번을 다시 한다(진단 없이 받은 응답뿐이었다).
   - `error` — 도구 에러 원문(권한 · 없는 job 등). 그대로 사용자에게 전하고 멈춘다.
   - `note` — 저장 훅이 없는 호스트다. 「저장 훅이 없을 때」대로 한다.
3. 완성된 HTML 을 낸다 — 빌더가 위 경로에 저장했다. 채팅에서 보여 줄 수 있는 호스트(Artifact 등)면 그 파일로 게시한다.
4. 완료 메시지는 아래 형식 그대로. 하이라이트는 B-1 응답의 `summary`(kind `optimized` · `current` 의 `media: "*"` 합계, 매체별 행)만 근거로 쓴다.

> ℹ️ 이 호스트의 Bash 기본 셸은 `sh`(dash)일 수 있다 — bash 전용 문법은 쓰지 않는다. `python3`이 없으면 `python`으로 부른다.

## 저장 훅이 없을 때

B-1 응답 원문을 **한 글자도 바꾸지 않고** Write 로 파일(예: `job.json`)에 저장한 뒤
`python3 assets/build_report.py --brand <브랜드> --json job.json` 으로 부른다. 값만 골라 옮겨 적기 · 행 줄이기는 금지다.

## 완료 메시지 형식

```
{브랜드명} 미디어믹스 결과 보고서({제안 달}) 생성 완료.
가장 인상적인 부분: {한 문장 하이라이트}.
— by LaightAI
```

실패 · 취소된 job 이면 하이라이트 대신 `사유: {error 원문}`(취소면 `사유: 취소된 계산`)을 쓴다.
빌더 출력의 `status` 가 `pending`·`running` 이면(10분을 기다려도 끝나지 않은 job) 이 형식 대신 아래를 쓴다 — 결과 수치는 아직 없으니 하이라이트를 쓰지 않는다.

```
{브랜드명} 미디어믹스 계산이 아직 끝나지 않았습니다({제안 달} 제안). 진행 상태 보고서를 만들었고, 나중에 결과를 다시 요청하면 목록에서 이 계산을 고를 수 있습니다.
— by LaightAI
```
