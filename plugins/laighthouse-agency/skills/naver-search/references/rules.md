# 네이버 검색량 요약 작성 규칙

수치 계산·순위·급증 판정은 스크립트(`prepare.py`)가 하고, 모델은 `facts`로 **요약 3문단**만 쓴다.
화면은 Sung Kang 님 수정본(11/04) 양식이다: 첫 문단은 굵은 결론, 둘째·셋째는 회색 보조 문단이고 셋째 앞에 "수치: "가 붙는다.
입력은 JSON 문자열 배열 `["<결론>", "<근거>", "<수치>"]`이다.

## 1. 문단별로 무엇을 쓰는가

1. **결론**(1~2문장): 자사 특이사항이 있었는지 먼저, 그다음 경쟁사 특이사항. 예: "현대카드는 최근 7일(10/28~11/3) 특이사항 없음. 경쟁사 중에는 롯데카드가 10/29(목) 하루 검색수가 급증했습니다."
   - 자사 특이사항 = 자사 급증(`spikes`). 경쟁사는 배수가 큰 것부터 둘까지.
2. **근거**: 브랜드별로 "브랜드: 근거" 형식. 자사는 급증이 없으면 지난주 같은 요일 대비 변동 범위(`vs_last_week_same_day_min`~`_max`)와 평일·주말 평균. 경쟁사 급증은 날짜·건수·지난주 같은 요일 값과 변화율. 끝에 "나머지 카드사는 특이사항 없습니다"처럼 한 구절.
3. **수치**("수치: "는 쓰지 않는다 — 화면이 붙인다): 자사 끝 7일(또는 범위 합계)과 변화율(`last7_vs_prev7`), 전체 브랜드 합계 변화(`all_brands.change_pct`), 점유율, 1위 브랜드.
   - 점유율은 `share_last7_pct`(끝 7일, 앞 7일 대비 pp) 또는 `share_range_pct`(범위 14일 미만)만 쓴다. 테넌트에 등록된 브랜드끼리 나눈 값이므로 "시장 점유율"이라고 쓰지 않는다.
   - `data_status`에 눈금 대조 차이 ±10% 초과로 나온 브랜드의 검색수 변화는 인용하지 않는다.
- 매출 효과, 광고주의 의도, 경쟁사의 전략은 쓰지 않는다.

## 2. 문장 규칙

- 특이사항은 **같은 요일 기준**으로 판단한다. 주말에 줄고 월요일에 느는 주기는 특이사항이 아니다. 근거는 `spikes`(같은 요일 유형 평균 대비),
  `vs_last_week_same_day_max`/`_min`(지난주 같은 요일 대비 — 그날이나 지난주 값이 급증 최소 건수 이상인 날만, `count`·`last_week` 함께),
  `weekday_avg`·`weekend_avg`(그 유형 날의 절반 미만만 쓸 수 있으면 null — 그때는 인용하지 않는다, 쓴 날 수 `weekday_days`·`weekend_days`)에서 고른다. 직전 7일 전체 평균과 비교해 쓰지 않는다.
- **수치는 facts에 있는 값만 인용한다.** 새로 더하거나 비율을 계산하지 않는다(같은 지표 두 값의 차·%p는 허용). `build_report.py`가 요약의 숫자를 대조한다.
- 인용 형식: `166,023건`, `-3.4%`, `26.5%(-0.1%p)`, `10/26(월)`.
- 같은 날 다른 지표가 함께 움직였다고 쓸 때는 "~와 같은 날"처럼 **연관**으로만 쓴다. 원인을 단정하지 않는다.
- 쓰지 않는 것: 수집·데이터 사정(집계 불완전, 수집 범위 밖, 눈금 대조 — `data_status`는 판단에만 쓴다), 방법론·정의(급증 기준·집계 방식), 내부 확인 요청.
  예외: 비교가 불가능할 만큼 데이터가 비면 그 사실 한 구절은 쓸 수 있다(예: "하루치가 모두 모인 날이 2일뿐").
- 범위의 날짜는 `M/D(요일)`로 쓴다. "당일"·"오늘"은 쓰지 않는다.
- 도구·스크립트·파일 이름은 요약에 쓰지 않는다.

## 3. 시간 예산

skill을 부른 뒤 **1분 안에** 끝나야 한다. 스크립트는 1초 안팎이다. MCP 1회, Bash 2회(prepare·build)면 된다.
