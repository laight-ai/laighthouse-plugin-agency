# 날씨 영향 요약 작성 규칙

수치·유형 판정은 스크립트(`prepare.py`)가 하고, 모델은 `facts`로 **요약 2단**만 쓴다(JSON 문자열 배열 `["<① 결론>", "<② 근거>"]`).
화면 양식: "한 줄 요약" 표시 없이 왼쪽 ① 결론(크게), 오른쪽 ② 근거(작게).
날씨가 성과에 영향을 준 것처럼 보이는지를 먼저 쓴다.
날씨 유형 기준: 비 1mm 이상, 폭우 30mm 이상(비 대신 표기), 폭염 최고기온 30℃ 이상,
무더위 불쾌지수(시간자료 최대) 75 이상. 시간자료가 6시간 넘게 빠진 날은 불쾌지수가 없다.
차트의 불쾌지수는 시간자료 일평균(`di_avg`), 기온은 일평균기온(`avg_ta`)이다.

## 1. 파트별로 무엇을 쓰는가

광고 성과가 있으면(`ad_performance.available`) 파트는 `① 날씨 영향이 있었나` → `② 근거`다.

1. **날씨 영향이 있었나**(1~2문장, 결론만): 비·기온·불쾌지수 중 성과 지표가 따라 움직인 것처럼 보이는 것이 있는지 한 문장으로.
   - 비: 지표별 `rain_gap.avg_change_pct`. 절댓값이 10% 이상이면 "비 온 날 ~이 줄어든/늘어난 것처럼 보인다", 미만이면 "뚜렷한 차이 없음".
   - 기온·불쾌지수: `corr_avg_ta`·`corr_di_avg` 절댓값이 0.5 이상이면 "~와 같은 방향으로 움직였다", 미만이면 "뚜렷한 관계 없음".
2. **근거**: 비 온 날 수와 날짜, 지표별 `avg_change_pct`(구매전환율이 클릭·매출과 다르게 움직였으면 두 값을 나란히 인용하고 서로 빼지 않는다). 비 온 날이 1~2일이면
   "비 온 날이 N일뿐이라 확정하기 이르다"를 붙인다. 특이 날씨(폭우·폭염·무더위)가 있으면 한 구절.

광고 성과가 없으면 파트는 `① 특이 날씨` → `② 근거`다.

1. **특이 날씨**: 폭우·폭염·무더위 일수(`day_counts`). 하나도 없으면 "특이 날씨 없음"(화면에도 '특이점 없음'이 나온다).
2. **근거**: 비 온 날 수(`rain_1mm_or_more`, 폭우 포함 — 날짜 목록을 직접 세지 않는다), 평균기온·불쾌지수 범위(`avg_ta_range`·`di_avg_range`).
   성과 영향은 쓰지 않는다.

- 차트마다 지표별 해석 한 줄은 스크립트가 facts 값으로 쓴다. 요약에 같은 문장을 되풀이하지 않는다.

## 2. 문장 규칙

- **수치는 facts에 있는 값만 인용한다.** 새로 계산하지 않는다. `build_report.py`가 요약의 숫자를 대조한다.
- 날씨가 성과를 "줄였다/늘렸다"고 단정하지 않는다. "~한 날 클릭은 ~보다 X% 적었다", "~처럼 보인다"처럼 **비교 사실·연관**으로만 쓴다.
  상관계수는 요일 주기와 섞여 있어 원인으로 쓰지 않는다.
- 광고 성과가 없는 브랜드에 성과 영향을 추측해 쓰지 않는다. 가상 수치를 쓰지 않는다.
- 날짜는 `M/D(요일)`, 도구·스크립트·파일 이름은 쓰지 않는다.

## 3. 시간 예산

1분 안에 끝나야 한다. MCP 2회(동시), Bash 2회(prepare·build)면 된다.
